# Дизайн: мобильная лента-свайп

> Дата: 2026-09-25 · Статус: утверждён к реализации
> Компаньон к PRD (§4, §7), `scoring_system_design.md` и `web/DESIGN.md`.

## 1. Контекст и цель

На телефоне Веракс уже выглядит как приложение (PWA, нижняя навигация,
безопасные зоны), но сценарий остаётся десктопным: один прогноз стоит четыре
экрана (список → карточка → циферблат → назад). Цель — сделать телефон
основным способом пользоваться площадкой: главная `/` становится лентой
открытых событий, по которым человек ещё не высказался, и одним жестом
(свайп влево / вправо) он отвечает «не случится / случится», следующее.

Решения владельца продукта:

- **Бинарный свайп.** Влево = `probably_no` (0.30), вправо = `probably_yes`
  (0.70), вверх = пропустить (только на клиенте). Кнопок «точно» / «50 на 50»
  в ленте нет; полный циферблат из пяти градаций остаётся на странице события
  `/events/[slug]`, куда ведёт шторка «Подробнее». Цена бинарности известна
  (при голосах только 0.3/0.7 вес события в скоринге ≤ ~0.5, калибровка из
  двух точек, квалификация требует вдвое больше сложных событий) и принята;
  маппинг «жест → грейд» живёт в одной константе `web/lib/feed.ts`.
- **Главная для всех** — лента. Лендинг переезжает на `/about`.
- **Отмена** — отложенная отправка (4 с) с тостом «Отменить»; удаления
  прогноза нет и не появляется.
- **Гость** видит ленту и сводку толпы, может свайпать; запись — только после
  входа по email и согласий. Первый свайп открывает шторку входа; если гость
  её закрыл, решения копятся в локальном ящике и отправляются после входа.

## 2. Границы и направление зависимостей

- Модель прогноза, скоринг, аудит **не меняются**: лента отправляет те же
  `PUT /events/{event_id}/prediction` с `confidence_grade`.
- Бэкенд получает **один новый эндпоинт чтения** `GET /events/feed` в модуле
  `events` и **один необязательный параметр** `next` у запроса magic-link в
  `identity`.
- Инварианты, которые лента обязана соблюдать: проценты на вводе не
  показываются; «да / нет» не красно-зелёные (`cool` / `warm`); сводка толпы
  видна всем и всегда (анти-якорение снято 18.08.2026, не восстанавливать);
  участие бесплатно, подписочного гейта нет; запись прогноза только для
  онбордившегося пользователя (PRD §7).

## 3. Модуль `events`: лента

### 3.1. Контракт

`GET /events/feed?limit=20&cursor=…&category_id=…` — `OptionalActorDep`.

Ответ `FeedPageResponse{items: FeedItemResponse[], next_cursor: str | null}`,
где `FeedItemResponse` = все поля `EventResponse` + `category{id, slug,
title}` + `crowd{total_count, distribution: {<grade>: int} (все 5 ключей),
mean_probability: Decimal | null}`.

Правила выборки: `status = open AND opens_at <= now AND closes_at > now`
(publish допускает `opens_at` в будущем; авто-закрытие крон делает раз в
минуту — окно обязательно); для вошедшего исключаются события с его
прогнозом (`NOT EXISTS` по `uq_predictions_user_event`); гость видит всё.
Порядок `closes_at asc, id asc` (скорее закроется — раньше). Keyset-курсор по
последней паре `(closes_at, id)`: base64url от `"<isoformat>|<uuid>"`; любой
мусор → `InvalidFeedCursorError` → 400. `limit` 1..50, по умолчанию 20.
`category_id` — точное совпадение, без поддерева (как в `/events`).

### 3.2. Слои

- `domain/value_objects.py` — `FeedCursor(closes_at, event_id)` с
  `encode()` / `decode()`; `domain/errors.py` — `InvalidFeedCursorError`.
- `ports/feed.py` — read-model `FeedCategoryRef`, `FeedCrowd`, `EventFeedItem`,
  `FeedQuery(now, limit, category_id, after, exclude_predicted_by)` и порт
  `EventFeedReader.page(query) -> list[EventFeedItem]`. Домен и порты о
  predictions не знают: распределение — `Mapping[str, int]` по строковым
  значениям грейдов.
- `application/use_cases.py` — `ListEventFeed(feed, clock)`: запрашивает
  `limit + 1`, режет, строит `next_cursor` из последнего элемента страницы.
- `adapters/feed_reader.py` — `SqlAlchemyEventFeedReader`: два запроса на
  страницу (страница событий с join категории; агрегат `GROUP BY event_id,
  confidence_grade` с `count` и `sum(probability)` по id страницы). Читает
  `PredictionORM` напрямую — прецедент `social/adapters/feed_gateway.py`.
- `api/` — схемы, `get_event_feed_reader` / `get_list_event_feed` в
  `dependencies.py` (часы — `ClockDep` модуля), роут **объявлен до**
  `GET /events/{event_ref}` (тот принимает любую строку). `app/main.py` —
  `InvalidFeedCursorError: 400`.

Миграция не нужна: `ix_events_closes_at` даёт range-scan, анти-джойн бьёт в
уникальный индекс. Если EXPLAIN на проде покажет Sort — частичный индекс
`(closes_at, id) WHERE status = 'open'` отдельной миграцией.

## 4. Модуль `identity`: возврат после входа

`POST /auth/email/request` принимает необязательный `next` (≤ 512).
`safe_return_path(raw)` в `domain/magic_link.py` пропускает только
относительный путь внутри сайта: начинается с `/`, не `//` и не `/\`, без
схемы, пробелов и управляющих символов; иначе `None`. Безопасное значение
встраивается в ссылку письма через `urlencode` (`letters.py` экранирует
`&`). На токене ничего не хранится: страница callback читает `next` из
своего URL и редиректит после обмена токена; онбординг принимает `?next=` и
ведёт туда после согласий. Фронтенд дублирует правило валидации.

## 5. Фронтенд

- `/` — `FeedScreen` (тёмная среда `bg-oracle`): стопка из трёх карточек,
  жест на Pointer Events без зависимостей (порог 35 % ширины карточки или
  флик; вверх — пропуск), штампы «НЕТ» / «ДА» / «ПРОПУСТИТЬ», кнопки-дубли
  «Нет / Пропустить / Да», клавиатура, `aria-live`, `prefers-reduced-motion`.
- Карточка: категория, срок, заголовок, описание, `MiniConsensus` + «Толпа
  склоняется: слово» + число прогнозистов, «Подробнее» (шторка с критериями,
  источником, ссылкой на страницу события и шерингом).
- Очередь отправки: 4 с на отмену, строгий порядок PUT, 409 → заметка,
  403 → онбординг с `next=/`, 401 → гейт, сеть → повтор и локальный ящик;
  `pagehide` → `fetch(keepalive)`; ящик доотправляется при следующем
  открытии ленты вошедшим пользователем (PUT идемпотентен).
- Навигация: вкладки Лента `/` · События · Топ · Ещё · Кабинет|Войти для
  всех; «Сезон» в листе «Ещё»; соцлента `/feed` → «Подписки»; нижняя панель
  тёмная на тёмных маршрутах, скрыта на `/about`; `start_url` PWA — `/`.
- Мобильные правки: `pt-safe` у шапки и тёмных экранов, сводка толпы в
  карточках `/events` на открытых событиях, устаревшие тексты.

## 6. Надёжность

- Курсор самодостаточен: страница не зависит от смещений, вставки и
  закрытия событий между страницами не ломают порядок.
- Отложенная отправка переживает закрытие вкладки (`keepalive`) и потерю
  сессии (ящик + повтор при следующем визите). Между показом карточки и
  коммитом событие может закрыться — 409 обрабатывается заметкой.
- Каждая запись прогноза берёт глобальную advisory-блокировку аудита —
  потолок пропускной способности общий; на текущих объёмах не проблема.
- Ссылка из письма, открытая в другом браузере, не увидит ящик исходного —
  гостевые свайпы восстанавливаются там, где сделаны (best effort).

## 7. Ошибки, тесты, миграции

- Ошибки: `InvalidFeedCursorError` → 400 (централизованно в `app/main.py`);
  `limit` вне 1..50 → 422 (pydantic); прочее как у существующих ручек.
- Тесты `events`: unit (курсор round-trip и мусор; use-case: окно, анти-джойн,
  гость, категория, `next_cursor` при переполнении, вторая страница без дублей
  при равных `closes_at`), integration (гость 200; `/events/feed` не 404;
  `limit=0|51` → 422; `cursor=garbage` → 400; предсказанное отсутствует у
  пользователя; 5 ключей распределения), e2e (реальный Postgres: гость и
  пользователь, суммы и `mean_probability`, `limit=1` + курсор).
- Тесты `identity`: `safe_return_path`; безопасный `next` в ссылке в
  URL-кодировке; небезопасные значения отбрасываются; > 512 → 422.
- Миграций нет.

## 8. Сознательно вне объёма

- Сохранение консенсуса на момент прогноза и его учёт в скоринге.
- Серверное хранение пропусков; картинки у событий; стрики и ачивки;
  пост-свайп «вы с большинством»; push; нативные приложения; пакетная
  сводка для `/events`.

## 9. Сводка ключевых решений

| Решение | Выбор | Почему |
|---|---|---|
| Ввод в ленте | бинарный свайп → `probably_no` / `probably_yes` | решение владельца; бэкенд не меняется |
| Где эндпоинт ленты | `GET /events/feed` в модуле events, до `/events/{event_ref}` | ресурс — события; прецедент «events-API знает predictions» |
| Пагинация | keyset `(closes_at, id)`, непрозрачный курсор | устойчива к вставкам и закрытиям |
| Сводка толпы в ленте | один `GROUP BY` на страницу | вместо N+1 запросов сводки |
| Отмена свайпа | отложенная отправка 4 с | удаления прогноза нет и не будет |
| Возврат после письма | `next` только в ссылке, валидация на сервере и клиенте | ничего секретного, хранить незачем |
| Гость | гейт на первом свайпе, дальше ящик | воронка без стены на каждом свайпе |
